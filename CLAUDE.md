# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Rhabdomancer** is a headless IDA plugin (written in Rust) that locates calls to potentially insecure API functions in binary files. It uses `idalib` ([idalib-rs](https://github.com/idalib-rs/idalib)'s Rust bindings to the IDA SDK) to auto-analyze a binary, finds the known bad API functions listed in its configuration, and marks each call site with a bookmark and a comment in the IDB, which it saves next to the binary.

## Build requirements

- IDA 9.4+ (see the README's compatibility table), with `IDADIR` set to the installation directory at both build time and runtime. The build script (`build.rs`, via `idalib-build`) checks common installation paths if it's unset, and only warns if it can't find IDA, so set it explicitly for non-standard locations (`export IDADIR=/path/to/ida`).
- LLVM/Clang, used by bindgen when building `idalib`. On Windows, `LIBCLANG_PATH` must also be set to the LLVM/Clang `bin` directory.
- Rust edition 2024.

## Commands

```bash
# Build
cargo build --release --locked     # optimized (LTO, stripped, O3)
cargo build --locked               # debug build (no debug info, for faster startup)

# Unit tests (no IDA database needed)
cargo test --lib --locked

# Integration tests (custom harness, needs a working IDA installation)
cargo test --test tests --locked

# Lint and format (CI enforces these as errors)
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings

# Documentation (CI enforces this as an error)
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --locked

# Dependency vulnerability audit (requires cargo-audit)
cargo audit

# Semver compatibility (requires cargo-semver-checks)
cargo semver-checks
```

`--workspace` follows the `rust-style` skill; this is a single crate, so it is equivalent to CI's `cargo clippy --all-targets --locked -- -D warnings`. `--no-deps` matches CI's `build.yml` doc step and skips documenting dependencies (`doc.yml`, which publishes to `gh-pages`, runs a plain `cargo doc --locked`).

CI's own `test` step only runs `cargo test --no-run` — a compile-only smoke check. Both test suites link against the IDA libraries, and the integration suite also needs a working IDA installation to analyze binaries, which CI runners don't have, so both only run locally.

## Architecture

This is a single crate: `src/main.rs` (CLI entry point) and `src/lib.rs` (all core logic).

- **`src/main.rs`** — CLI entry point. Parses a single binary path argument, calls `force_batch_mode()` to suppress IDA UI, then delegates to `lib::run()`.
- **`src/lib.rs`** — Core analysis logic. Public entry point: `run(filepath: impl AsRef<Path>) -> anyhow::Result<BookmarkIndex>`. It is the only public item: everything else, including `PREFIX` (`"[BAD "`, private since 1.0), is internal, so the public API stays minimal (making items public later is non-breaking; CI runs `cargo-semver-checks`). A library API for other crates (e.g., a `scan()` returning findings without printing) would be designed separately rather than by exporting these CLI-oriented types. The annotation text is an external contract (see Output).

### Key types and functions

- `KnownBadFunctionsConfig`: Mirrors the configuration file (`high`/`medium`/`low` name lists); only used as the deserialization source of `KnownBadFunctions`. All three lists are required, and `#[serde(deny_unknown_fields)]` rejects any other key, so a misspelled priority (e.g., `meduim`) fails loudly instead of being silently ignored.
- `KnownBadFunctions`: Loads the configuration into a single `HashMap<String, Priority>` keyed by normalized name. Deserialized via `#[serde(try_from = "KnownBadFunctionsConfig")]`: the `TryFrom` impl normalizes every name and rejects the configuration at the first name that is empty or is listed under multiple priorities (after normalization), so `parse()` deserializes straight into `Self` with `toml::from_str`. `load()` parses the file at `RHABDOMANCER_CONFIG` if set and not empty (an empty value counts as unset, so clearing the variable restores the built-in list) (read with `fs::read_to_string`, adding the file path as `anyhow` context to read and parse errors), or the built-in `DEFAULT_CONFIG` otherwise, printing `[*] Using built-in configuration (set RHABDOMANCER_CONFIG to use a custom one)` so the way to customize is shown on every run (with no fallback to a file on disk, so which configuration is used never depends on the source tree); the unit tests call `parse()` directly, so they exercise the same parsing path as `load()`. Duplicates are detected with `*functions.entry(name).or_insert(priority) != priority`, which keeps the first occurrence and compares against it in one expression. `lookup()` normalizes a `&str` and returns the stored normalized name (via `get_key_value`, borrowed from the map) and its priority, so callers never normalize twice; it is unit-testable without an IDB. `lookup(func_name, is_thunk)` tries, in order, the normalized name, `strip_ucrt_prefix()`'s result, and `strip_ida_suffix()` applied to that (or to the normalized name), the last only for evident stubs (`is_thunk`, or a UCRT wrapper); the candidates are `[Option<&str>; 3]` flattened into a `find_map`, and the two helpers return `None` when there's nothing to strip, so no candidate is looked up twice. An exact match always wins, so a configured name such as `strcpy_1` keeps its own priority, and the unprefixed name is tried before stripping the suffix, so a custom `foo_2` matches `__o_foo_2`.
- `BadFunctions<'a>`: Pure data: the bad functions found in the opened IDB, in a single `BTreeMap<(Priority, FunctionId), (Function<'a>, &'a str)>`, so iteration visits high, then medium, then low priority, each ordered by function ID. In ELF binaries a bad API function usually matches twice, as its `.plt` stub (printed as `(thunk)`) and as its import, and both are kept on purpose, so their call sites are listed twice (on `tests/data/ls` all 10 functions appear as identical thunk/import pairs; `tests/data/double_xref` pins it for `system`). Don't deduplicate them: dropping the stub by name would lose its marks whenever the import's traversal doesn't reach its callers (an unrelated function that normalizes to the same name, e.g. a local `_strlen` vs `strlen@plt`, or a stub IDA doesn't link to the import). A structural check (drop the stub only if the import has an XREF from inside it) would be safe, but was rejected in favor of simplicity: the repetition is cosmetic, since the `bookmarked` set marks each call site once. `find_all()` is a single `filter_map(...).collect()` that fetches each function's name once, passes `lookup()` whether the function is flagged as a thunk (`FunctionFlags::THUNK`), (an FFI call plus a `String` allocation) and stores the function with the normalized name returned by `lookup()`, borrowed from `KnownBadFunctions` (hence `find_all(idb: &'a IDB, bad: &'a KnownBadFunctions)`, a single lifetime for both borrows). `iter()` exposes the entries as flat `(priority, id, func, name)` tuples in map order, so consumers such as `CallMarker` don't depend on the map's layout; it has no `#[must_use]` because `impl Iterator` already is (adding one triggers clippy's `double_must_use`).
- `CallMarker<'a>`: Annotates an IDB, holding the context that marking needs: the `&'a IDB` itself, its `PltSegments`, and `bookmarked`, the set of addresses that already carry one of rhabdomancer's bookmarks (see below), so none of them is passed around as a parameter. `mark_all(&found)` iterates `found.iter()` (ignoring the function ID) and totals the counts returned by `mark_calls()` with `.sum()` over `Result<BookmarkIndex, IDAError>`, which stops at the first error; `run()` adds the `anyhow` context. `mark_calls()` receives each function's priority and name, formats the description (`[BAD n] <normalized name>`) itself, and returns the count from `traverse_xrefs()` (`0` for a function without XREFs); `traverse_xrefs()` counts newly added bookmarks with `saturating_add`. Keep IDB-dependent marking state (e.g., a visited set for thunk cycles) here rather than in `BadFunctions`. Idempotency: `CallMarker::new()` builds `bookmarked` from every bookmark index (`get_address(idx)` + `get_description_by_index(idx)` containing `PREFIX`), and `traverse_xrefs()` marks an address only if `self.bookmarked.insert(from)` succeeds, which also records the bookmarks added during the run, so a call site reached through several bad functions is bookmarked once. Never look a bookmark up by address (`get_description(ea)`): IDA overlays bookmarks added at an already bookmarked address, and a lookup by address returns only one of them, which may be a user's own; that made rhabdomancer re-mark such call sites on every run and even twice within one (pinned by `test_user_bookmark_at_call_site()`). The marking methods take `&mut self` because the set is updated during the walk. Comments don't need this: the `get_cmt(from)` check sees the whole comment text. Both checks deliberately use `contains(PREFIX)`, not `starts_with`: for comments it's required, because `append_cmt` adds the tag after any existing comment; for bookmarks it keeps one of rhabdomancer's bookmarks that a user edited by prepending text recognized (so it isn't marked again), at the cost of a user's own bookmark that merely mentions the prefix counting as rhabdomancer's. Every version has written descriptions starting with `[BAD `, so either check recognizes older IDBs.
- `Priority` enum: `High`/`Medium`/`Low` — maps to BAD 0/1/2. Variants are declared from highest to lowest priority, and the derived `Ord` follows declaration order (no explicit discriminants or `#[repr]`), which is what orders `BadFunctions`' map: keep this order when editing the enum. `level()` maps each variant to its tag digit with an explicit `match` (deliberately not a cast, so tags don't depend on declaration order), and `description()` builds `[BAD n] <name>` as `format!("{PREFIX}{}] {func_name}", self.level())`, so tags are derived from the `PREFIX` constant and can't drift from it. The `description_formats_tag_and_name` unit test pins the full format with literals.
- `CallMarker::traverse_xrefs(target, desc)`: Iteratively walks the XREFs to `target` with a worklist of addresses: each popped address's chain is walked with `for xref in iter::successors(first_xref_to(addr, ...), XRef::next_to)` (an address without XREFs yields nothing, so `mark_calls()` just passes `func.start_address()`). Handles `.plt` thunk indirection for ELF binaries: when an XREF comes from a `.plt` segment, the containing thunk's start address (`function_at(from).map(|func| func.start_address())`, no `BADADDR` sentinel) is queued and its XREFs walked after the current chain; the explicit worklist keeps deep indirection from overflowing the call stack. A `visited` set, seeded with `target`, makes each address queued at most once. That fixes a real bug: when a `.plt` stub references the import more than once, as IDA sees AArch64 stubs (`tests/data/double_xref`), the stub's XREFs were walked once per reference, listing its callers twice (pinned by `test_thunk_with_repeated_xrefs()`). It also makes cyclic `.plt` references terminate. Such cycles don't occur in compiler-generated binaries as IDA analyzes them (on `tests/data/ls`, IDA splits every lazy-binding `.plt` stub into its own function, and nothing the walk visits is referenced from them; the 47 `jmp PLT0` XREFs form no cycle), but they can in crafted binaries or if IDA delimits `.plt` functions differently (e.g., one function spanning PLT0 and the stubs would reference itself), and rhabdomancer runs on untrusted input. The integration tests can't exercise the cycle case; it was checked by forcing a self-cycle (terminates with the guard, hangs without it). Call-site order is not a contract: a chain's direct callers are listed before the callers reached through its thunks (on `tests/data/ls` imports have no direct callers, so the output matches the earlier recursion-like order). Early `continue`s (for `.plt` and non-code XREFs) avoid an `if`/`else if` without `else`. `self.idb.bookmarks()` (a zero-cost `PhantomData` wrapper) is bound once per traversal.
- `PltSegments`: The address ranges of all `.plt*` segments of the IDB, collected once by `PltSegments::new()` (no per-call FFI lookups). `contains()` checks whether an address falls within any of them; the ranges are half-open `Range<Address>` values, matching IDA's `range_t` (`end_ea` excluded), which unit tests pin without an IDB.
- `normalize_name()`: Strips leading dots/underscores from function names for cross-platform matching.
- `strip_ucrt_prefix()` and `strip_ida_suffix()`: The fallbacks used by `lookup()`, each returning `None` when there's nothing to strip. `strip_ucrt_prefix()` takes the raw name and strips the `__o_`/`_o_` prefix of Universal CRT wrappers, normalizing the rest (`__o_malloc` gives `malloc`, `__o__wpopen` gives `wpopen`); it checks the raw name because the leading underscores tell a wrapper apart from a function such as `o_write`. `strip_ida_suffix()` strips one `_<digits>` suffix, which IDA appends when a name is already in use (e.g., `memset_0`, `CreateProcessW_0`). Without them, such PE import stubs were never matched: on an MSVC ARM64 `cmd.exe`, rhabdomancer marked 104 call locations instead of 301 (166 calls through `memset_0` alone), and on `tests/data/import_stubs` 10 instead of 22. IDA adds the suffix only when the plain name is taken (e.g., by a symbol), which is why the same stub can be named `memcpy` in one build and `memcpy_0` in another. The suffix is only stripped from thunks and UCRT wrappers because 121 built-in names are short plain words (`read`, `write`, `free`, `stat`, ...), so stripping it from any function would match helpers such as `read_16`; every suffixed match found in `cmd.exe` and `tests/data/import_stubs` is a thunk, and the three non-thunk ones are UCRT wrappers (`__o_malloc`, `__o__wpopen`, `_o_rand_0`), so the gate loses none of them. Deliberately a fallback in the name lookup rather than a different design: matching from the `__imp_X` entries would also catch direct `call [__imp_X]` calls (none in the binaries checked) but needs a rule for which referencing functions are stubs, and `Function::calc_thunk_target()` returns `None` for every ARM64 thunk in `cmd.exe`. A thunk named like `strcpy_2` that isn't a `strcpy` stub would still match, which is accepted. Not handled: IDA's `j_` prefix of MSVC incremental-linking thunks (`j_strcpy`), whose callers are missed because only `.plt` stubs are followed.
- `function_name()`: Returns a function's name, or `[no name]` if it has none; a private copy of haruspex's `function_name()` (same fallback text), rather than a haruspex dependency for a one-liner. Caller names are printed as `{from:#X} in {}` with `function_name(&func).escape_debug()`, since they come from the binary (terminal escapes, bidi overrides), the same technique as haruspex and augur; an XREF outside any function prints the `[unknown]` literal, without allocating. The bad-function headers print the normalized name from the configuration, which isn't escaped.

## Output

Results go to stdout (`println!`); everything else (banner, progress, summary, timing, errors) goes to stderr (`eprintln!`), with the prefixes `[*]` for progress, `[+]` for success and summaries, `[-]` for information, and `[!]` for warnings and errors, and the elapsed time as `{:.1} seconds`. Preserve this split when adding new output. The results are the bad-function headers and call-site locations.

stdout layout:

```
                                  # blank line before each bad function
[BAD {level}] {name} (thunk)      # ` (thunk)` only for functions in a .plt segment
{addr:#X} in {caller}             # one line per call site, `[unknown]` outside any function
...
```

Each call site is also annotated in the IDB with a bookmark and a comment `[BAD n] <normalized name>`, where `n` is the priority level (0 = high, 1 = medium, 2 = low). The annotation text is an external contract, documented in the README: users and scripts search IDBs for it, and IDBs annotated by previous versions carry it, so never change it.

## Configuration

All "bad" functions are defined in `conf/rhabdomancer.toml`, grouped into `high`, `medium`, and `low` arrays. The file is embedded in the binary at build time as `DEFAULT_CONFIG` (`include_str!`), replacing the earlier path built from `CARGO_MANIFEST_DIR`, which broke binaries whose source tree was moved or deleted (e.g., after `cargo install`); editing it requires a rebuild. A custom configuration file can be used instead by setting the `RHABDOMANCER_CONFIG` environment variable to its path. `conf/` must stay in the published package (not in `Cargo.toml`'s `exclude`), since `include_str!` needs it when building from crates.io. The loader reads the file with `fs::read_to_string` and deserializes it with the `toml` crate (`toml::from_str`, features `std`, `serde`, and `parse` only) via serde; the parse error type is imported as `TomlError`. Each name may appear under only one priority (leading dots/underscores are ignored when comparing names); otherwise loading fails with an error naming the (normalized) duplicate. Repeats within the same priority are harmless and merged. Entries that are empty once normalized (e.g. `""`, `"_"`, `"."`) are also rejected, with an error showing the original spelling. All three arrays are required, and any other key is rejected (`deny_unknown_fields`), so a typo can't silently drop a priority's functions.

## Error handling

- Functions below `run()` return concrete error types (`IDAError` from marking, `TomlError` from parsing); only `run()` and `KnownBadFunctions::load()`, which combines reading the file and parsing it, use `anyhow`, adding context.
- The configuration is loaded before the binary is opened, so a configuration error never creates an IDB.
- Marking stops at the first error (`CallMarker::mark_all()` sums over `Result`).
- Finding no calls is not an error: `run()` returns `Ok(0)`, since a re-run on an annotated IDB legitimately marks nothing (unlike augur and haruspex, which reject zero results, since their output would be empty).
- XREFs outside any function are printed as `[unknown]` and still marked.
- `main()` prints errors as `[!] Error: {err:#}` (the full context chain) and exits with `ExitCode::FAILURE`.

## Lint policy

All clippy lint groups (`all`, `pedantic`, `nursery`, `cargo`, `restriction`) are enabled as warnings in the workspace lints of `Cargo.toml` (the same configuration in augur, haruspex, and rhabdomancer) and treated as errors by `cargo clippy -- -D warnings`. A curated set of restriction lints is explicitly allowed (e.g., `implicit_return`, `question_mark_used`, `print_stdout`, `pattern_type_mismatch`), and `linker_messages = "allow"` is a temporary workaround for <https://github.com/idalib-rs/idalib/issues/81>. Notably forbidden outside tests:

- `unwrap`, `expect`, `panic`, `todo`, `unimplemented`, `unreachable`, `dbg_macro`: use `?`, `anyhow` context, and `Option` combinators instead.
- Unsafe blocks without a `// Safety:` comment (`undocumented_unsafe_blocks`).
- Undocumented items (`missing_docs`, `missing_docs_in_private_items`): every item has a doc comment, private ones and test helpers included.

`clippy::min_ident_chars` is enabled, so single-character identifiers (e.g. `|s|`, `for f in`) are flagged — use descriptive names like `name`, `func`, `idx`. Clippy's default `allowed-idents-below-min-chars` still permits `i`, `j`, `x`, `y`, `z`, `w`, and `n`, and parameters that keep a trait's own name (such as `f` in `fmt::Display::fmt`) are not flagged either; prefer descriptive names (e.g. `idx`) anyway.

Pure functions whose result matters carry `#[must_use]`, private ones included (clippy's `must_use_candidate` only flags public items), e.g., `Priority::level()`, `KnownBadFunctions::lookup()`, `PltSegments::contains()`, `function_name()`, and `normalize_name()`.

Use `#[expect(clippy::some_lint, reason = "...")]`, never `#[allow]`, to locally suppress a lint that genuinely cannot be avoided, in both library code and tests. The only one in the codebase: `panic_in_result_fn` (test assertions, as a module-level `#![expect]` in `tests/main.rs` and on `mod tests` in `src/lib.rs`). `env::set_var`/`remove_var` are `unsafe` in Rust edition 2024; wrap them in `unsafe {}` with a `// Safety:` comment explaining the single-threaded context, as `run_with_config()` in `tests/main.rs` does.

Taplo enforces TOML formatting (`.taplo.toml`: 120-char line width, 4-space indent).

The crate-level documentation in `src/lib.rs` is assembled in a specific order to satisfy two restriction lints simultaneously, and should not be "simplified" back to a plain `#![doc = include_str!("../README.md")]`:

- `#![doc = env!("CARGO_PKG_DESCRIPTION")]` is always present (pulls the `description` from `Cargo.toml` with no duplication) so the crate is documented in every build configuration — this satisfies `missing_docs`, which runs without `--cfg doc`.
- `#![cfg_attr(doc, doc = include_str!("../README.md"))]` pulls in the README only under `cfg(doc)`, satisfying `clippy::doc_include_without_cfg`.
- The `#![doc = ""]` between them forces a Markdown paragraph break so the description and the README's leading heading don't merge.

## Tests

### Unit tests

`#[cfg(test)] mod tests` at the end of `src/lib.rs` covers the logic that doesn't need an IDB: priority mapping, normalization of both configuration and function names, merging of duplicates within the same priority, rejection of names that normalize to empty (and no match for function names that do), the `lookup()` fallbacks (IDA's numeric suffix stripped from thunks but not from other functions such as `read_16`, the UCRT prefix stripped only with its leading underscores so that `o_write` doesn't match, the unprefixed name tried before stripping the suffix, exact matches taking precedence, and no match for other suffixes and prefixes such as `strcpy_s`, `strcpy_0x`, or `strcpy_0_1`, even for thunks), rejection of names listed under multiple priorities (via `TryFrom`, checking the exact message names each duplicate once normalized, and via `parse()`), rejection by `parse()` of unknown keys, missing priorities, wrong types, and invalid TOML (the first two checking `toml`'s `unknown field`/`missing field` messages), validity of the built-in configuration (`DEFAULT_CONFIG`, the same constant the binary uses, so a duplicate in `conf/rhabdomancer.toml` fails the unit tests), `Priority::description()`'s exact `[BAD n] <name>` format, `PltSegments::contains()` (start included, end excluded, every range checked; test values are built from `(start, end)` pairs via a `plt()` helper, because clippy's `single_range_in_vec_init` rejects `vec![start..end]`), and the `Priority` order `High < Medium < Low` (which determines processing order, so reordering the variants fails a test).

### Integration tests

`tests/main.rs` holds the custom-harness integration tests, structured like augur's: documented constants at the top, a `main()` that calls `idalib::force_batch_mode()` and then one `test_*` function per scenario (in augur's and haruspex's order: the successful runs, then the failures), and one `check_*` function per assertion (each printing its own `[*] Checking ... Ok.` line). Scenarios:

1. `test_default_configuration()` (against `tests/data/ls`): runs the real binary (via `run_binary()`, as augur's and haruspex's first scenarios do, pinning the CLI output in the same analysis) and checks, with literals: success; stdout line counts by kind (`check_number_of_output_lines()`: `N_BAD_FUNCTIONS` = 20 blank lines and 20 `[BAD n]` headers, `N_CALL_SITE_LINES` = 172 call-site lines, i.e., the 86 locations listed under both stub and import, and nothing else); the whole line `0x2C5F in sub_2C30` (`check_stdout_line()`); the whole stderr summary line `[+] Marked 86 new call locations` (`check_summary()`); and with `check_priority_order()` that the levels of the `[BAD n]` headers never decrease (high, then medium, then low) and that more than one level appears (on `ls`: medium, then low), so the check isn't vacuous (the `Priority` unit test pins only the enum's order; this pins that the output follows it, and reversing `BadFunctions::iter()` fails it). It then checks bookmark count (`N_MARKS`), that every bookmark description starts with `BAD_PREFIX`, comment count, and that the comment at every bookmarked address starts with that bookmark's description, and finally runs `rhabdomancer::run()` again on the same IDB and asserts 0 new marks (idempotency lives here because it depends on this scenario's IDB). `run()`'s return value on new marks is checked by scenarios 2, 6, and 7.
2. `test_custom_configuration()`: runs with `CUSTOM_CONFIG_TOML` via `RHABDOMANCER_CONFIG`, asserts exactly 13 marks, and runs the same bookmark count, comment count, and comment-matches-bookmark checks as scenario 1, plus an exact check that every bookmark description is `[BAD 1] ` followed by one of the normalized names in `CUSTOM_MEDIUM`. Since the custom config includes decorated names (`_fwrite`, `.memset`), this verifies that both bookmarks and comments use normalized names.
3. `test_binary_without_calls()`: runs against `tests/data/no_calls`, a minimal macOS arm64 Mach-O binary built from `tests/data/no_calls.c` (`cc -O0 -o no_calls no_calls.c`, the same binary as augur's `no_strings`), and asserts 0 marks, 0 bookmarks, and 0 comments.
4. `test_thunk_with_repeated_xrefs()`: regression test for duplicated call-site lines. Runs the real `rhabdomancer` binary (`env!("CARGO_BIN_EXE_rhabdomancer")`, via `run_binary()`, with `RHABDOMANCER_CONFIG` removed) against `tests/data/double_xref`, an ARM64 ELF whose `main` calls `system` through `system@plt`, checks that it succeeds, and pins its exact stdout (`DOUBLE_XREF_LISTING`): IDA sees the AArch64 stub (`adrp`/`ldr`/`add`/`br`) referencing the `system` import more than once, so without `traverse_xrefs()`' visited set the stub's XREFs were walked once per reference and `0x7F4 in main` was listed twice. The bookmark check already deduplicated the marks, so only the stdout listing shows the bug, which is why this scenario captures stdout through a subprocess (`rhabdomancer::run()` prints it directly). It also checks 1 bookmark, 1 comment, and comments matching bookmarks. The listing shows `system` twice (thunk and import), which is deliberate (see `BadFunctions`).
5. `test_import_stubs_with_numeric_suffix()`: regression test for PE import stubs that IDA names with a numeric suffix. Runs the real binary against `tests/data/import_stubs`, an x86-64 PE built with mingw from `tests/data/import_stubs.c` (build command in the source; renamed without `.exe`, since IDA names the IDB of `foo.exe` `foo.exe.i64`, which `reset_idb()` wouldn't remove) and stripped of debug info only: its symbols take the plain names, so IDA names the stubs `strcpy_0`, `system_0`, `memcpy_0`, `malloc_0`, and `getenv_0` (a fully stripped build has no `_0` names, so it wouldn't test anything). Checks success, that `strcpy_0` exists and is a thunk (`check_thunk_exists()`, so the scenario fails loudly instead of passing vacuously if a future IDA names the stubs differently), the `[BAD 0] strcpy` header and the `0x1400014AB in helper` call site (`check_stdout_line()`), the summary `[+] Marked 22 new call locations` (10 without the fallbacks), 22 bookmarks and comments, and comments matching bookmarks. The UCRT prefix isn't exercised here (mingw doesn't use it); the unit tests cover it.
6. `test_user_bookmark_at_call_site()`: regression test for overlaid bookmarks. Creates the IDB of `tests/data/double_xref` with `IDB::open_with(.., true, true)` (so it's saved) and a user bookmark (`USER_BOOKMARK_DESC`) at the call site `USER_BOOKMARK_ADDR` (`0x7F4`), then runs rhabdomancer twice: the first run must mark exactly 1 location (before the fix it marked 2, because the call site is reached through both `system (thunk)` and `system` and each lookup by address returned the user's bookmark), the second must mark 0, and the IDB must hold 2 bookmarks with the user's unchanged. It doesn't run `check_comments_match_bookmarks()`, since the user's bookmark has no matching comment.
7. `test_user_comment_at_call_site()`: regression test for the comment check. Creates the IDB of `tests/data/double_xref` with a user comment (`USER_COMMENT`, via `add_user_comment()`) at the call site `USER_COMMENT_ADDR` (`0x7F4`), runs rhabdomancer twice (1 mark, then 0), and checks 1 bookmark, 1 comment, and that the comment is exactly `USER_COMMENT_MARKED` (`"user comment\n[BAD 0] system"`: `append_cmt` adds the tag after the user's text, separated by a newline). This pins the `contains(PREFIX)` comment check: with `starts_with`, the tag was appended on every visit (4 times over the two runs). It doesn't run `check_comments_match_bookmarks()`, since the comment doesn't start with the tag.
8. `test_empty_configuration_variable()`: runs the real binary against `tests/data/no_calls` with `RHABDOMANCER_CONFIG` set to an empty value and checks with `check_binary_succeeded()` that it succeeds, i.e., uses the built-in configuration instead of failing to read an empty path. It checks the exit status, not the `Using built-in configuration` line, so rewording that line doesn't break the test. A subprocess is needed because the in-process harness removes the variable (see below).
9. `test_invalid_configuration()`: runs with `INVALID_CONFIG_TOML` (the same function under two priorities once normalized) and checks that `run()` fails with the duplicate error and that no IDB file is created, since the configuration is loaded before the binary is opened.
10. `test_missing_configuration()`: points `RHABDOMANCER_CONFIG` at a configuration file that doesn't exist (`config_path(MISSING_CONFIG)`, removed first if present) and checks that `run()` fails with an `io::Error` of kind `NotFound` somewhere in its error chain (found by downcasting each cause; deliberately not a message: the OS's wording varies by platform, and rhabdomancer's own context message can be reworded without breaking the test) and that no IDB file is created.
11. `test_missing_binary()`: runs against the nonexistent `tests/data/missing` and checks that `run()` fails with `failed to analyze binary file` and creates no IDB file.
12. `test_invalid_arguments()`: runs the real binary (via `run_binary()`) with no arguments, two arguments, `-h`, and `--help`, and checks with `check_usage()` that each run fails, prints `Usage:` to stderr and nothing to stdout, and creates no IDB file for `tests/data/no_calls` (the two-argument case passes it twice). Covers the only branching in `src/main.rs`; IDA never opens a database here, so it's fast.
- `BAD_PREFIX` is deliberately the literal `"[BAD "` (`PREFIX` is private anyway): the annotation text is an external contract (users and scripts search IDBs for it), so an accidental change to the tags rhabdomancer writes must fail the tests. The same applies to other expected values (`CUSTOM_MEDIUM`, the `[BAD 1] ` tag, error substrings): keep them as literals.
- `main()` removes `RHABDOMANCER_CONFIG` before running any scenario, so a value exported in the developer's shell can't replace the built-in configuration that the in-process scenarios expect (all but 2, 9, and 10, which set their own) (`run_binary()` also removes it from the subprocess's environment).
- Helpers: `reset_idb()` removes all IDB files of a binary, packed (`.i64`) or unpacked (`IDB_EXTENSIONS`), if present (every scenario starts and ends with it, so a crashed run doesn't poison the next); `open_idb()` opens an IDB and enables hidden comments/functions/instructions/segments before checks; `config_path()` returns a configuration file path under `env::temp_dir()` (named by label and process ID, never inside the source tree); `run_with_config_path()` sets `RHABDOMANCER_CONFIG` to a path for one run, then unsets it; `run_with_config()` writes a configuration file at `config_path(label)`, runs via `run_with_config_path()`, then removes the file, returning the run's result (nested in the outer `anyhow::Result` for file I/O errors) so that callers can check expected errors. `run_binary(args, config)` runs the real binary with `args` and `RHABDOMANCER_CONFIG` set to `config` or removed (`None`), forwards its stderr, and returns its `process::Output`, without checking its status: scenarios expecting success call `check_binary_succeeded()` (same names and pattern as augur and haruspex), and the stdout checks (`check_listing()`, `check_priority_order()`) take the `Output`. Scenarios `drop()` their IDB before rhabdomancer reopens the database.

Conventions shared by the augur, haruspex, and rhabdomancer harnesses:

- All scenarios run sequentially in the same process; the harness stops at the first failed check, and its progress messages go to stderr.
- Expected values that pin an external contract (CLI output lines, summaries, file names, annotation tags, error substrings) are literals, never production constants, so that an accidental change fails the tests.
- Expected errors are matched against the full error chain (`format!("{err:#}")`), i.e., what users see; OS-dependent failures are checked by downcasting to `io::ErrorKind`, not by message.
- Only the module-level `#![expect(clippy::panic_in_result_fn)]` is needed: fallible lookups use `.context(...)?` instead of `expect`, and conversions use `try_from` instead of `as`.
- New checks must be shown to fail: temporarily break the behavior they guard, run the suite, restore. If an earlier check catches the break first, break it differently, so that the new check is shown to fail on its own.

## IDA integration notes

- `IDB::open_with(path, true, true)` opens or creates an `.i64` IDB file with auto-analysis enabled and the database kept after closing.
- `idalib::force_batch_mode()` must be called before opening any database (suppresses IDA UI); `main()` and the test harness both call it first.
- IDA must run on the main thread and isn't thread-safe, so standard `#[test]` functions, which run on worker threads, can't use it: that's why the integration tests use a custom harness (`harness = false`).
- Objects derived from an `IDB` (e.g., `Function`, `CFunction`) must be dropped before the `IDB` itself, since their destructors call into IDA: idalib's lifetimes don't enforce this at implicit scope-end drops, and getting it wrong hangs the process.
- Names from the analyzed binary (function names, strings) are untrusted: print them escaped with `str::escape_debug()` (or `{:?}`) at the print site, and build file names from them only through a sanitizer.
- To probe IDA's view of a binary, write a temporary `examples/` program (`cargo run --example ...`), then delete it.
- Annotation is idempotent — existing bookmarks/comments are not duplicated, even when a user's own bookmark shares the address (see `CallMarker`).
- `.plt` sections in ELF binaries require following one level of thunk indirection to reach the real import; `traverse_xrefs` handles this.

## CI workflows

- **`build.yml`** — lint/build/test matrix across Linux, macOS, and Windows, plus a `zizmor` job that audits `.github/workflows/*.yml` for security issues (credential handling, injection, etc.).
- **`doc.yml`** — builds rustdoc and pushes it to the `gh-pages` branch on `v*` tags; its `checkout` step needs persisted git credentials to `git push` later, so it carries a `# zizmor: ignore[artipacked]` suppression comment.
- To suppress a specific zizmor finding, add an inline `# zizmor: ignore[<rule-id>]` comment on the flagged step with a short justification, rather than disabling the rule globally.
